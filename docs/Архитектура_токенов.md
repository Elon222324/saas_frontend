# Архитектура управления токенами в SaaS-платформе

## Обзор

В приложении используются **два типа токенов** для обеспечения безопасности и разграничения доступа:

1. **Токен пользователя (User Access Token)** - для доступа к центральному API админки
2. **Токен сайта (Site Token)** - для доступа к API конкретного сайта

## Типы токенов

### 1. Токен пользователя (User Access Token)

**Назначение**: Аутентификация пользователя в центральной панели управления

**Хранение**: `localStorage.getItem('access_token')`

**Использование**:
- Запросы к бэкенду админки (`VITE_API_URL`)
- Управление сайтами (создание, запуск, остановка)
- Получение списка сайтов
- Управление пользователями
- Получение токенов сайтов

**Примеры эндпоинтов**:
```
POST {VITE_API_URL}/user/login
GET  {VITE_API_URL}/sites/get_all/
POST {VITE_API_URL}/sites/add_new
GET  {VITE_API_URL}/orders/{siteName}/  # Старое API (в процессе миграции)
```

### 2. Токен сайта (Site Token)

**Назначение**: Аутентификация для работы с данными конкретного сайта

**Типы**:
- `admin-token` - содержит `user_id`, `site_name` (предпочтительно)
- `site-token` - резервный вариант без `user_id`

**Получение**: 
```javascript
// Через новый централизованный хук
import { useSiteToken } from '@/hooks/useSiteToken'
const { data: token } = useSiteToken('t4a')
```

**Хранение**: В React Query кеше (5 минут), не в localStorage

**Структура токена**:
```json
{
  "user_id": "123",
  "site_name": "t4a",
  "exp": 1234567890
}
```

**Использование**:
- Прямые запросы к site-api конкретного сайта
- Управление категориями товаров
- Управление опциями товаров
- Управление экстра-опциями
- В будущем: управление заказами

**Примеры эндпоинтов**:
```
GET    https://{site}.{VITE_BASE_DOMAIN}/site-api/admin/categories/
POST   https://{site}.{VITE_BASE_DOMAIN}/site-api/admin/categories/
PATCH  https://{site}.{VITE_BASE_DOMAIN}/site-api/admin/categories/{id}
DELETE https://{site}.{VITE_BASE_DOMAIN}/site-api/admin/categories/{id}
```

### Алгоритм получения токена сайта

```javascript
// 1. Проверяем кеш React Query
const cachedToken = queryClient.getQueryData(['siteToken', siteName])
if (cachedToken && !isStale) {
  return cachedToken // Возвращаем из кеша
}

// 2. Пытаемся получить admin-token (приоритетный)
const adminTokenResponse = await fetch(
  `${VITE_API_URL}/user/admin-token/${siteName}`,
  {
    headers: {
      Authorization: `Bearer ${localStorage.getItem('access_token')}`
    }
  }
)

if (adminTokenResponse.ok) {
  const token = await adminTokenResponse.json()
  return normalizeToken(token) // Сохраняется в кеш автоматически
}

// 3. Fallback на site-token
const siteTokenResponse = await fetch(
  `${VITE_API_URL}/user/site-token/${siteName}`,
  {
    headers: {
      Authorization: `Bearer ${localStorage.getItem('access_token')}`
    }
  }
)

const token = await siteTokenResponse.json()
return normalizeToken(token)
```

## Момент получения токенов

### Стратегия: Ленивая загрузка (Lazy Loading)

Токены **НЕ** получаются заранее для всех сайтов. Вместо этого:

1. ✅ Токен запрашивается **только когда нужен**
2. ✅ При первом обращении к данным сайта
3. ✅ Автоматически кешируется на 5 минут
4. ✅ Переиспользуется всеми компонентами

### Примеры сценариев

#### Сценарий 1: Пользователь заходит в настройки сайта

```
1. User → /settings/t4a
2. SiteSettingsContext монтируется
3. Вызывает useSiteToken('t4a')
4. Токен получается и кешируется
5. Все дочерние компоненты используют кешированный токен
```

#### Сценарий 2: Пользователь работает с Products

```
1. User открывает Products
2. useCategories вызывает useSiteToken('t4a')
3. Если токен уже в кеше → используется сразу
4. Если нет → получается и кешируется
5. useProducts использует тот же кешированный токен
```

#### Сценарий 3: Переключение между сайтами в Orders

```
1. User выбирает сайт 't4a'
2. useSiteToken('t4a') → получает и кеширует токен
3. Заказы загружаются
4. User выбирает сайт 't5b'
5. useSiteToken('t5b') → получает новый токен (параллельно)
6. Токен 't4a' остается в кеше еще 5 минут
7. При возврате к 't4a' → токен берется из кеша
```

## Интеграция в компонентах

### Вариант 1: Через контекст (для настроек сайта)

```javascript
// В контексте
import { useSiteToken } from '@/hooks/useSiteToken'

export const SiteSettingsProvider = ({ children }) => {
  const { domain } = useParams()
  const { data: token, isLoading: tokenLoading } = useSiteToken(domain)
  
  const siteToken = token ? { token, raw: token } : null
  
  return (
    <SiteSettingsContext.Provider value={{ siteToken, ... }}>
      {children}
    </SiteSettingsContext.Provider>
  )
}

// В компонентах
const { siteToken } = useSiteSettings()
```

### Вариант 2: Напрямую в компонентах (для независимых страниц)

```javascript
import { useSiteToken } from '@/hooks/useSiteToken'

export default function OrdersPage() {
  const [selectedSite, setSelectedSite] = useState('')
  const { data: token, isLoading } = useSiteToken(selectedSite)
  
  // Используем токен в запросах
}
```

### Вариант 3: В кастомных хуках (для модулей данных)

```javascript
import { useSiteToken } from '@/hooks/useSiteToken'

export function useCategories(siteName) {
  const { data: siteToken } = useSiteToken(siteName)
  
  return useQuery({
    queryKey: ['categories', siteName, siteToken],
    enabled: Boolean(siteToken),
    queryFn: async () => {
      const response = await fetch(url, {
        headers: { Authorization: `Bearer ${siteToken}` }
      })
      return response.json()
    }
  })
}
```

## Обработка ошибок

### Типичные ошибки

```javascript
// 1. Отсутствует access_token пользователя
Error: "Отсутствует access_token пользователя"
→ Решение: Перелогиниться

// 2. Токен пользователя истек
HTTP 401 при получении токена сайта
→ Решение: Обновить через /user/refresh

// 3. Нет прав на сайт
HTTP 403 при получении токена сайта
→ Решение: Проверить права доступа

// 4. Токен сайта истек
HTTP 401 при запросе к site-api
→ Решение: React Query автоматически обновит при refetch
```

### Логирование

Все операции с токенами логируются:

```javascript
// Получение токена
🔑 [useSiteToken] → Получаем токен для сайта: t4a
✅ [useSiteToken] ← Токен получен для: t4a
🧾 [useSiteToken] Claims: { user_id: "123", site_name: "t4a", exp: "..." }

// Использование в хуках
🔑 [useCategories] → запрашиваю новый API: https://t4a.domain.com/site-api/admin/categories/
🔑 [useCategories] ← статус ответа: 200 OK
✅ [useCategories] ← построенное дерево: [...]
```

## Производительность

### Кеширование

- **Время жизни кеша (staleTime)**: 5 минут
- **Время хранения (cacheTime)**: 10 минут
- **Количество повторов (retry)**: 2
- **Дедупликация**: автоматическая

### Оптимизации

1. ✅ **Один запрос на сайт** - токен получается один раз
2. ✅ **Переиспользование** - все компоненты используют один токен
3. ✅ **Параллельные запросы** - токены для разных сайтов получаются параллельно
4. ✅ **Prefetch** - можно предзагрузить токены заранее если нужно

```javascript
// Пример prefetch для часто используемых сайтов
queryClient.prefetchQuery({
  queryKey: ['siteToken', 't4a'],
  queryFn: () => fetchSiteToken('t4a')
})
```

## Безопасность

### Хранение токенов

- ❌ **НЕ** храним токены сайтов в localStorage
- ✅ Токены сайтов хранятся только в памяти (React Query кеш)
- ✅ Токен пользователя в localStorage (для обновления)
- ✅ Токены автоматически удаляются при закрытии вкладки

### Передача токенов

- ✅ Только через заголовок `Authorization: Bearer ...`
- ❌ Никогда не передаем токены в URL
- ❌ Никогда не передаем токены в query параметрах

### Истечение токенов

- Токены сайтов имеют короткое время жизни (обычно 15-30 минут)
- При истечении автоматически запрашивается новый
- Refresh токен пользователя обновляется автоматически (axios interceptor)
