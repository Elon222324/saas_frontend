# 🌐 Sites Management - Owner Panel

## Обзор

Раздел управления сайтами в Owner Panel предоставляет полный функционал для администрирования сайтов пользователей через единый интерфейс.

**Требования:** Роль `super_admin`

## Структура

```
src/pages/OwnerPanel/Sites/
├── api/
│   └── sites.js              # API функции для работы с сайтами
├── components/
│   ├── AddSiteModal.jsx      # Модальное окно добавления сайта
│   └── UserSitesModal.jsx    # Модальное окно управления сайтами пользователя
├── index.jsx                 # Главная страница со списком всех сайтов
└── README.md                 # Эта документация
```

## API Функции (api/sites.js)

### Управление сайтами пользователей

Основаны на документации `info/ADMIN_SITES_API_DOCUMENTATION.md`

#### `addSiteToUser(userId, siteData)`
Добавить сайт пользователю с **полным автоматическим деплоем**
- **Эндпоинт:** `POST /api/user/admin/users/{user_id}/sites`
- **Параметры:**
  - `userId` - ID пользователя
  - `siteData` - Объект с данными: `{ user_id, domain }`
- **Что происходит:**
  1. ✅ Создание записи в БД
  2. ✅ Создание директорий и файлов сайта
  3. ✅ Создание базы данных PostgreSQL
  4. ✅ Инициализация всех таблиц сайта
  5. ✅ Создание и запуск Docker контейнера
  6. ✅ Сайт автоматически становится доступен
- **Возвращает:** Созданный сайт со статусом `running`
- **Время:** 30-60 секунд
- **Примечание:** API ключи больше НЕ требуются - создаются автоматически

#### `getUserSites(userId)`
Получить все сайты пользователя
- **Эндпоинт:** `GET /api/user/admin/users/{user_id}/sites`
- **Параметры:** `userId` - ID пользователя
- **Возвращает:** Объект с `{ user_id, sites_count, sites: [] }`

#### `getSiteById(siteId)`
Получить информацию о сайте по ID
- **Эндпоинт:** `GET /api/user/admin/sites/{site_id}`
- **Параметры:** `siteId` - ID сайта
- **Возвращает:** Объект сайта с данными владельца

#### `deleteSiteFromUser(userId, siteId)`
**Полностью удалить** сайт пользователя со всей инфраструктурой
- **Эндпоинт:** `DELETE /api/user/admin/users/{user_id}/sites/{site_id}`
- **Параметры:** `userId`, `siteId`
- **⚠️ ВНИМАНИЕ:** Необратимая операция! Все данные будут потеряны!
- **Что происходит:**
  1. ✅ Остановка Docker контейнера
  2. ✅ Удаление контейнера
  3. ✅ Удаление записи из БД SaaS
  4. ✅ Удаление всех файлов и директорий
  5. ✅ Удаление базы данных PostgreSQL
  6. ✅ Очистка кэша фронтенда
- **Время:** 10-30 секунд

### Существующие функции

- `fetchAllSites()` - Получить все сайты системы
- `updateSite(siteId, siteData)` - Обновить сайт
- `deleteSite(siteId)` - Удалить сайт
- `createSite(siteData)` - Создать сайт

## Компоненты

### AddSiteModal

**Назначение:** Модальное окно для добавления нового сайта пользователю

**Props:**
- `onClose` - Функция закрытия модального окна
- `onCreate` - Callback после создания сайта
- `preselectedUserId` - Опциональный ID предварительно выбранного пользователя

**Функциональность:**
- Выбор пользователя из списка
- Отображение информации о выбранном пользователе (email, роль, количество сайтов)
- Ввод домена сайта (с валидацией уникальности)
- Информационный блок о полном автоматическом деплое
- Визуализация всех шагов деплоя
- Индикатор процесса (30-60 секунд)
- Примечание: API ключи создаются автоматически

**Пример использования:**
```jsx
<AddSiteModal
  onClose={() => setShowModal(false)}
  onCreate={(newSite) => {
    console.log('Создан сайт:', newSite)
    loadSites()
  }}
  preselectedUserId={5} // опционально
/>
```

### UserSitesModal

**Назначение:** Модальное окно для просмотра и управления всеми сайтами конкретного пользователя

**Props:**
- `user` - Объект пользователя `{ id, email, user_name }`
- `onClose` - Функция закрытия модального окна
- `onUpdate` - Callback при изменении списка сайтов

**Функциональность:**
- Отображение всех сайтов пользователя
- Информация о каждом сайте (ID, домен, статус, дата создания, путь, имя контейнера)
- Цветовая индикация статусов (запущен, остановлен, деплой, создан, ошибка и т.д.)
- Кнопка добавления нового сайта
- Кнопка обновления списка
- Действия над сайтом:
  - Открыть сайт в новой вкладке
  - Перейти к настройкам сайта
  - **ПОЛНОСТЬЮ УДАЛИТЬ** сайт (контейнер + файлы + БД) с предупреждением
- Красное информационное сообщение о необратимости удаления
- Подтверждающий диалог с детальным списком что будет удалено
- Сообщение об успешном удалении со списком удаленных компонентов

**Пример использования:**
```jsx
<UserSitesModal
  user={{ id: 5, email: 'user@example.com', user_name: 'John' }}
  onClose={() => setSelectedUser(null)}
  onUpdate={() => loadAllSites()}
/>
```

### Главная страница (index.jsx)

**Функциональность:**
- Отображение таблицы всех сайтов в системе
- Колонки: ID, Имя, Владелец (с кнопкой просмотра всех сайтов), Email владельца, Домен, Путь, Статус, Дата создания, Действия
- Кнопка "Добавить сайт пользователю" в заголовке
- Счетчик общего количества сайтов
- Цветовая индикация статусов сайтов
- Иконка "Пользователи" для быстрого просмотра всех сайтов конкретного пользователя
- Интеграция с модальными окнами AddSiteModal и UserSitesModal

## Workflow использования

### Добавление сайта пользователю

1. Нажать кнопку "Добавить сайт пользователю" на главной странице Sites
2. Выбрать пользователя из списка
3. Просмотреть информацию о пользователе (email, роль, количество сайтов)
4. Ввести домен сайта (только домен, без протокола)
5. Ознакомиться со списком операций автоматического деплоя
6. Нажать "Создать и задеплоить сайт"
7. Подождать 30-60 секунд (происходит полный автоматический деплой)
8. Сайт будет создан и сразу доступен со статусом `running`
9. API ключи создаются автоматически - ничего не нужно настраивать вручную

### Просмотр сайтов пользователя

1. На главной странице Sites найти любой сайт нужного пользователя
2. Нажать иконку "Пользователи" рядом с ID владельца
3. Откроется модальное окно со всеми сайтами этого пользователя
4. В модальном окне можно:
   - Добавить новый сайт
   - Обновить список
   - Открыть любой сайт
   - Перейти к настройкам
   - Удалить сайт из БД

### Удаление сайта

⚠️ **ВНИМАНИЕ:** Функция `deleteSiteFromUser` выполняет **ПОЛНОЕ НЕОБРАТИМОЕ УДАЛЕНИЕ**!

**Процесс удаления (автоматический, 10-30 секунд):**
1. Система показывает подробное подтверждающее сообщение
2. После подтверждения выполняется:
   - ✅ Остановка Docker контейнера
   - ✅ Удаление контейнера
   - ✅ Удаление записи из БД SaaS
   - ✅ Удаление всех файлов и директорий
   - ✅ Удаление базы данных PostgreSQL
   - ✅ Очистка кэша фронтенда
3. Все данные сайта безвозвратно удалены
4. Система показывает сообщение об успешном удалении

**Никаких дополнительных действий не требуется** - всё делается автоматически!

## Статусы сайтов

- 🟢 **running** - Контейнер запущен и работает (финальный статус после деплоя)
- ⚡ **deploying** - Сайт в процессе деплоя (временный статус, 30-60 сек)
- 🔴 **stopped** - Контейнер остановлен
- 🔵 **created** - Сайт создан в БД, контейнер не запущен
- ⚠️ **not_found** - Контейнер не найден
- ❌ **error** - Ошибка получения статуса
- ❓ **unknown** - Статус неизвестен (проблемы с API)

## Интеграция с другими разделами

### Связь с Users
- Компоненты Sites используют API функцию `fetchAllUsersWithSites()` из раздела Users
- UserDetailsModal в разделе Users отображает сайты пользователя (только для просмотра)
- Управление сайтами (добавление/удаление) находится только в разделе Sites

### API эндпоинты
- Использует центральный API через `VITE_API_URL`
- Требует access_token из localStorage
- Все запросы включают авторизацию через Bearer token
- Обработка ошибок 401 (токен истек), 403 (нет прав), 404 (не найдено), 400 (некорректные данные)

## Важные замечания

1. **Автоматический деплой:** При создании сайта выполняется полный деплой (30-60 сек), сайт сразу доступен
2. **API ключи НЕ требуются:** Создаются автоматически при деплое сайта
3. **Уникальность доменов:** Домены должны быть уникальными в системе
4. **Полное удаление:** Удаление через UI полностью удаляет сайт (контейнер + файлы + БД) - необратимо!
5. **Статусы в реальном времени:** Статусы получаются через Docker API при каждом запросе
6. **Логирование:** Все операции логируются с префиксами 🌐 [FunctionName]
7. **Процесс занимает время:** Деплой 30-60 сек, удаление 10-30 сек
