# 📚 Руководство: Добавление новых блоков в редактор страниц

## 🎯 Обзор процесса

Когда вы создаёте новый блок (например, `PromoStories`), нужно зарегистрировать его в трёх местах:

1. **Editor** - компонент для редактирования блока
2. **Preview** - компонент для визуализации блока  
3. **API интеграция** - endpoints для создания/обновления блока

---

## 📋 Шаг за шагом

### ✅ Шаг 1: Структура папки блока

Каждый блок должен быть расположен в папке:
```
src/pages/Sites/SiteSettings/PagesTab/BlocksEditor/forms/{BlockName}/
```

**Обязательные файлы:**
- `index.js` - экспорт редактора
- `Editor.jsx` - главный компонент редактора
- `Appearance.jsx` - вкладка дизайна/настроек внешнего вида
- `ItemsEditor.jsx` - вкладка содержимого/данных
- `{name}Schema.js` - схема для settings (внешний вид)
- `{name}DataSchema.js` - схема для data (содержимое)
- `{name}Preview.jsx` - **НОВОЕ** компонент предпросмотра

### ✅ Шаг 2: Создание Preview компонента

**Файл:** `src/pages/Sites/SiteSettings/PagesTab/BlocksEditor/forms/{BlockName}/{BlockName}Preview.jsx`

```jsx
import { useEffect, useState } from 'react'
import { PreviewWrapper } from '@preview/PreviewWrapper'
import { applyCssVariablesFromUiSchema } from '@preview/utils/applyCssVariables'
import { useSiteSettings } from '@/context/SiteSettingsContext'

export default function PromoStoriesPreview({ settings = {}, data = {}, commonSettings = {} }) {
  const { data: globalSiteData } = useSiteSettings()
  const [styleVars, setStyleVars] = useState({})

  useEffect(() => {
    if (!globalSiteData?.ui_schema) return

    applyCssVariablesFromUiSchema(globalSiteData.ui_schema)
    const vars = {}
    Object.entries(settings).forEach(([key, val]) => {
      if (key.includes('color') || key.startsWith('bg_')) {
        vars[`--${key.replace(/_/g, '-')}`] = val
      }
    })
    setStyleVars(vars)
  }, [settings, globalSiteData?.ui_schema])

  // Здесь отрисовываем компонент с preview
  return (
    <PreviewWrapper>
      <div style={styleVars}>
        <div className="max-w-full mx-auto">
          {/* Ваш компонент для отображения */}
          <YourComponent settings={settings} data={data} commonSettings={commonSettings} />
        </div>
      </div>
    </PreviewWrapper>
  )
}
```

### ✅ Шаг 5: Добавление API для создания блока

**Файл:** `src/pages/Sites/SiteSettings/PagesTab/BlocksEditor/hooks/useBlocksApi.js`

Добавьте mutation для создания блока:

```javascript
const createBlock = useMutation({
  mutationFn: async ({ type, label }) => {
    const res = await fetch(`${baseApiUrl}/create/${slug}`, {
      method: 'POST',
      headers: getHeaders(),
      body: JSON.stringify({ type, label }),
    })
    if (!res.ok) throw new Error(`Error creating block: ${res.statusText}`)
    return res.json()
  },
  onSuccess: () => {
    refetchSiteSettings()
  },
})

return {
  // ... остальные mutations
  createBlock: createBlock,  // ← ДОБАВЬТЕ
}
```

## 🔄 Как формируются блоки (Data Flow)

### 1️⃣ При загрузке страницы:

```
Backend (БД) 
  → GET /site-api/admin/pages/{slug}
  → Frontend получает data.blocks[slug] = [...]
  → BlocksEditor парсит и сортирует блоки
  → BlockListSidebar отображает список
```

### 2️⃣ При добавлении нового блока:

```
Клик "Добавить новый блок"
  → Modal открывается
  → Пользователь выбирает тип
  → POST /site-api/admin/blocks/create/{slug}
  → Backend создаёт блок в БД и возвращает новые данные
  → refetchSiteSettings() обновляет контекст
  → BlockListSidebar обновляется автоматически
```

### 3️⃣ При редактировании блока:

```
Пользователь меняет данные в Editor
  → onChange вызывает handleBlockChange
  → Изменения накапливаются в unsavedBlocks
  → Клик "Сохранить"
  → POST /site-api/admin/blocks/update-all/{slug}
  → Backend обновляет блоки
  → Страница обновляется
```

## 🚀 Как это работает на фронтенде

### URL: `http://localhost:5173/settings/t4a/pages/index`

1. **Страница загружается** → Fetches блоки для `index` страницы
2. **BlockListSidebar** → Отображает список всех блоков с:
   - Типом (`banner`, `promo_stories` и т.д.)
   - Порядком
   - Статусом (активен/неактивен)
   - Кнопкой "Добавить новый блок" внизу

3. **BlockEditorPanel** → Когда выбран блок, показывает:
   - Preview компонент (если зарегистрирован)
   - Editor с табами "Данные" и "Дизайн"

4. **Добавление блока:**
   - Клик на кнопку → Modal с выбором типа
   - Выбор типа → API запрос → Блок создан → List обновлен

## 🔐 Backend API

Ваш backend должен поддерживать endpoint:

```
POST /site-api/admin/blocks/create/{slug}
Headers: Authorization: Bearer {token}
Body: {
  "type": "promo_stories",
  "label": "Мои истории"
}
Response: { ... блок данные ... }
```

Возвращаемый блок должен содержать:
- `id` - уникальный ID в контексте страницы
- `real_id` - ID в БД
- `type` - тип блока (`promo_stories`)
- `label` - название блока
- `order` - порядок
- `active` - активен ли
- `settings` - JSON с настройками оформления
- `data` - JSON с содержимым

## ❓ FAQ

### Q: Как я знаю, какой тип блока выбрать при создании?
**A:** Типы блоков должны совпадать с тем, как они называются в БД. Уточните у backend-разработчика.

### Q: Что если backend не вернул новый блок правильно?
**A:** Проверьте:
- Ответ статуса (200 vs 400/500)
- Структуру ответа в Network tab браузера
- Логи backend'а
- Endpoint существует: `/site-api/admin/blocks/create/{slug}`

### Q: Как добавить больше типов блоков в modal?
**A:** Обновите `AVAILABLE_BLOCK_TYPES` в `AddBlockModal.jsx`

### Q: Блок добавился, но не отображается в редакторе?
**A:** Скорее всего нет Preview компонента. Добавьте логику в `BlockDetails.jsx` renderPreview.
