## Авторизация и маршрутизация API (админка ↔ сайт)

Этот документ описывает, как мы аутентифицируемся и куда отправляем запросы:
- какие бывают бэкенды (админка и сайт),
- как формируются URL для каждого типа,
- какой токен использовать и в каком заголовке,
- эталон на примере категорий товаров.

### Термины
- «Бэкенд админки» — центральное API панели управления. Базовый URL задаётся `VITE_API_URL`.
- «Бэкенд сайта» — API конкретного сайта, доступ по домену вида `{site}.{VITE_BASE_DOMAIN}`.
- `site_name` — имя сайта внутри платформы (часто в коде используется значение с суффиксом `_app`). Для доменного имени сайта в URL суффикс нужно удалить.

---

## Токен и заголовки

- Все запросы, которые идут напрямую на «бэкенд сайта», требуют JWT токен админки сайта в заголовке:

```
Authorization: Bearer <token>
Content-Type: application/json
```

- Структура JWT токена должна содержать клеймы:

```json
{
  "user_id": "<строка|число>",
  "site_name": "<имя сайта без суффикса>",
  "exp": 1234567890
}
```

### Где берём токен
Токен всегда выдаёт «бэкенд админки»:

```
POST {VITE_API_URL}/user/site-token/{site}
```

Где `{site}` — домен сайта без суффикса, например `t4a`.

На фронте токен сохраняем как объект вида `{ token: string, raw: any }` и передаём дальше только поле `token`.

---

## Формирование URL

### Бэкенд админки
- База: `{VITE_API_URL}`
- Используется для платформенных операций (управление сайтами `/sites/*`, получение токенов `/user/*`, прочие централизованные операции).
- Пример: `POST {VITE_API_URL}/user/site-token/{site}`

### Бэкенд сайта
- База: `https://{site}.{VITE_BASE_DOMAIN}/site-api`
- ВАЖНО: `{site}` — БЕЗ суффикса `_app`.
- Пример построения на фронте:

```js
const siteNameForApi = siteName.replace('_app', '')
const base = `https://${siteNameForApi}.${import.meta.env.VITE_BASE_DOMAIN}/site-api`
```

## Эталон: Категории товаров

Все операции с категориями выполняются НАПРЯМУЮ на «бэкенд сайта» под префиксом `/admin/categories/` и требуют админский JWT токен сайта.

### Эндпоинты (бэкенд сайта)
- Список категорий: `GET /admin/categories/`
- Получить по ID: `GET /admin/categories/{id}`
- Получить по slug: `GET /admin/categories/by-slug/{slug}`
- Создать: `POST /admin/categories/`
- Обновить: `PATCH /admin/categories/{id}`
- Удалить: `DELETE /admin/categories/{id}`

Полный URL формируется так:

```
https://{site}.{VITE_BASE_DOMAIN}/site-api/admin/categories/...
```

Где `{site}` — имя без суффикса `_app`.

### Клиентские правила (фронт)
- Перед любым запросом к категориям дожидаемся получения `siteToken.token` из контекста.
- В заголовке используем только этот токен: `Authorization: Bearer ${siteToken.token}`.
- Не используем `localStorage` токены для запросов к «бэкенду сайта».
- В react-query добавляем зависимость ключа от `siteToken.token`,
  и `enabled: Boolean(siteToken?.token)` чтобы не трогать API без токена.

Минимальный пример списка категорий:

```js
const siteNameForApi = siteName.replace('_app', '')
const url = `https://${siteNameForApi}.${import.meta.env.VITE_BASE_DOMAIN}/site-api/admin/categories/`

const res = await fetch(url, {
  method: 'GET',
  headers: {
    Authorization: `Bearer ${siteToken.token}`,
    'Content-Type': 'application/json',
  },
  credentials: 'include',
})
```

### Ошибки и валидация
- 401: ошибки аутентификации. Бэкенд возвращает `{ error: { code, message } }` — показываем `message`.
- 400: ошибки валидации (например, неверный `slug`) — собираем `detail[]` и выводим сообщения.
- 404/409: категория не найдена/конфликт (дубликат `slug` или `code`).

## Быстрый чек-лист для исполнителя

1) Получить токен сайта с «бэкенда админки»:
   - `POST {VITE_API_URL}/user/site-token/{site}`;
   - берём строку токена и кладём в `Authorization: Bearer ...`.

2) Определить тип API:
   - если «бэкенд сайта»: собираем `https://{site}.{VITE_BASE_DOMAIN}/site-api/...` (без `_app`).
   - если «бэкенд админки»: используем `{VITE_API_URL}`.

3) Для категорий товаров ВСЕГДА используем «бэкенд сайта» и префикс `/admin/categories/`.

4) В коде фронта:
   - ждём `siteToken.token` перед запросом (`enabled: Boolean(siteToken?.token)`),
   - не используем токены из `localStorage` для запросов к сайту,
   - учитываем обработку 401/400/404/409.

---

## Примеры «до/после» (миграция)

До (через бэкенд админки):

```
GET {VITE_API_URL}/products/{siteName}/categories/all
```

После (напрямую на бэкенд сайта):

```
GET https://{site}.{VITE_BASE_DOMAIN}/site-api/admin/categories/
```

Где `{site} = siteName.replace('_app', '')`.
